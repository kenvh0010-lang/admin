A $327.6M Mars Mission Lost to a Unit Mismatch

On September 23, 1999, NASA lost the three-hundred-twenty-seven-point-six-million-dollar Mars Climate Orbiter mission after nine months in deep space because two elite engineering teams used incompatible measurement units.

  • 286-day journey ended as the $125M probe dipped too low
  • Two elite aerospace teams assumed different force units

Source: NASA Mars Climate Orbiter Mishap Board Phase I Report (Nov 10, 1999)

Pound-Force Seconds Met Metric Newton-Seconds

Lockheed Martin ground software exported thruster impulse in English pound-force seconds while NASA JPL navigation software expected metric newton-seconds, skewing trajectory math by four-point-four-five times and burning up the hundred-twenty-five-million-dollar spacecraft.

  • Lockheed ground software wrote impulse in pound-force seconds
  • NASA JPL trajectory code read values as metric newton-seconds

Source: NASA Mars Climate Orbiter Mishap Board Phase I Report (Nov 10, 1999)

Modules Pass Internally While Boundaries Fail

Both teams employed world-class engineers whose separate code modules worked internally, yet nobody enforced an automated end-to-end interface test where one system's raw output file became the next system's input.

Name Units in Every Header and Assert Boundaries

Embed explicit unit names directly into every spreadsheet header, database column, and API key, such as amount_usd_cents or duration_seconds, and validate every external file automatically at the boundary before running downstream math.

Complex operations rarely fail inside one smart specialist's head; they disintegrate at silent handoffs between tools where unit assumptions go completely unchecked.
